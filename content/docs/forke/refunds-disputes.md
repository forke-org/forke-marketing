title: Refunds & disputes
description: What happens when work is rejected, a task expires, or a founder and developer disagree.
---

Because the budget is held in escrow and code is only merged after approval, problems are about releasing money the right way, never about chasing it.

## When work is rejected

| What happened | What happens to the money |
| --- | --- |
| The submission fails automated checks | Nothing moves. The developer can fix it and resubmit before the deadline. |
| The founder requests changes | It stays in escrow while the same developer revises. |
| The deadline passes with no submission | The task goes back to the feed; the money stays in escrow for the next developer. |

## Refunds

If a founder decides not to go ahead with a task, refunds follow the [refund policy](/refund). Code is never delivered to the founder before approval, so there's never a case of "the work was used but not paid for".

## Disputes

If a founder and developer genuinely disagree about whether the work meets the criteria, either can raise it with Forke through [support](/docs-demo/forke/support). Forke looks at the task, the acceptance criteria, the submission and the verdict card, and decides how escrow is released.

Developers at level 19 and above get fast-tracked dispute resolution.

> [!TIP]
> Most disputes come from vague acceptance criteria. Founders: see [Writing a great task](/docs-demo/forke/posting-tasks).
